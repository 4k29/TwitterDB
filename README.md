# TwitterDB UI

TwitterDBの公開UIです。投稿アーカイブ、分析データ、分類、削除状態、学習済みモデルは含みません。非公開 `4k29/TwitterDB-data` から、端末のブラウザ内に保存したFine-grained GitHubトークンで取得します。既存の投稿DB、分類修正、削除状態、キャッシュ、分析グラフ、月別レビューはそのまま利用できます。

## 投稿案の予測・反応の記録

分析グラフの「投稿案の予測・反応の記録」から開きます。日本語本文の2文字組の類似度、任意入力のテーマ・形式を使い、似た投稿・理由・中央値・件数を表示します。分類は選択または修正でき、自動推定は行いません。未入力時は本文だけを使います。処理はブラウザのWorker内で完結し、外部AIサービスには送信しません。

初期対象は **アーカイブ取得時点のいいねの参考推定** です。観測の経過時間が不明・混在するため、24時間後・7日後や最終実績ではありません。比較対象の10–90%点は「実績の幅」であり、校正した予測区間ではありません。確率、自信度、伸びる保証は提供しません。入力変更後は再予測してください。保存は明示的な操作だけで行い、投稿案も非公開データ側に保存されます。

予測の選択は古い60%→検証20%→最終テスト20%の順です。検証期間で20件以上かつ最近100件の中央値に対しMAEとlog1p MAEが改善した場合に本文類似法を採用し、それ以外は最近中央値を採用します。分類の付与・修正時点が不明なので、時系列検証の入力に分類は使いません。テーマを入力した現在の推定と、本文だけの検証結果は同一モデル精度とは主張しません。複雑な学習モデルは未採用です。最終テストは選択に使いません。

IDと正規化した同一本文、2文字組Dice類似度0.9以上の近似重複を除外します。語彙は学習せず、過去投稿のみを検索します。固定時点のラベルは、その予測日時までに取得済みのものだけを学習に使います。アーカイブの反応取得日時は不明なので、その時系列評価は投稿日で区切った「取得時点実績」の回顧検証に限られます。厳密な前向き検証には新しい履歴が必要です。データコミット・履歴revision・アルゴリズム版が変わると再計算し、学習済みデータは永続キャッシュしません。

## 手動登録・保存先

1. 投稿DBの同期設定で非公開 `TwitterDB-data` にアクセスするトークンを設定します。閲覧はContents read、履歴保存はContents writeが必要です。既存トークンをサーバーやActionsへ転送しません。
2. 投稿予測画面で `https://x.com/p_horeer/status/投稿ID` と実際の投稿日時を登録します。元ページの所有者と種別を確認してください。返信・リポストは除外、引用は含めます。判定不能は保留となります。
3. 実際に公開した本文を任意で保存できます。固定時点の投稿前モデルの学習にはこの本文が必要です。保存済みの投稿前予測は投稿前に保存したものだけを紐付けできます。
4. 元ページで確認した反応を入力して保存します。空欄はnull、0はゼロです。概数は値・元表示・概数フラグを保持します。取得日時は保存時の実時刻で、過去の欠測は埋めません。取得失敗も別の履歴として保存でき、直前の成功値を上書きしません。
5. 停止・再開を操作できます。7日後は定期取得を終了し、履歴は保持します。未確認の種別を確認後に確定する操作もあります。

保存先は非公開側の `tracking/state.json` です。元アーカイブ、削除状態、分類、月別レビューは変更しません。追跡投稿、実取得スナップショット、予測履歴、発見の成功／失敗を分離して保存します。同一投稿＋runIdは一度だけ保存します。SHAを用いたGitHub更新競合では最新データを再読込して最大3回まで試行し、競合相手の履歴を保持します。認証・通信エラーで空の履歴に戻しません。

推移は実際の経過時間に点で表示します。減少も保持し、前回成功からの増加と観測間隔を表示します。欠測・概数から精密な増分は計算しません。比較時点は1時間±30分、24時間±2時間、7日±2時間のうち最も近い**正確な**観測です。概数や観測がない場合は欠測です。取得は7日以内で終了するため、7日比較は通常166〜168時間の観測を使い、正確な経過時間も表示します。

## 固定時点・初動モデル

24時間・7日の実観測と公開本文が蓄積すると、予測対象を切り替えてその履歴のみで投稿前予測できます。少数時は「不足」と表示します。1時間の実観測がある投稿では、投稿前モデルと別に、過去投稿の1時間→24時間／7日の比率中央値を使う初動モデルを実装しています。予測時点に完了していた他投稿だけを使用し、5件未満や初動ゼロの比較投稿は比率モデルで使いません。取得時に利用可能な初動予測を非公開履歴に保存し、後の実績と比較します。初動モデルは未検証の参考推定で、区間・確率は提供しません。

## ブラウザ取得を手動実行する

Node.js 24とPlaywrightが必要です。ツールは公開側のコード、データは別の非公開チェックアウトです。

```sh
cd TwitterDB
npm ci
npx playwright install --with-deps chromium
TWITTERDB_DATA_DIR=/absolute/path/TwitterDB-data X_ACCOUNT=p_horeer node tools/track.mjs --discover
```

既存Chromiumを使う場合は `CHROMIUM_PATH=/usr/bin/chromium` を追加します。認証セッションが必要な場合は、**別途用意した**Playwright storage stateのローカルファイルパスを `X_STORAGE_STATE` に指定します。ログイン処理・Cookie抽出は自動化しません。通常の許可されたログインで取得し、アクセス権0600等で保管してください。公開コード、Git、ログ、スクリーンショット、成果物に保存しないでください。`*.storage-state.json` は無視対象です。

少数URLでの確認:

```sh
CHROMIUM_PATH=/usr/bin/chromium node tools/probe-browser.mjs p_horeer https://x.com/p_horeer/status/POST_ID
```

Chromium起動と実ページ取得、同一URLの2回取得、プロフィール発見を確認します。出力は成功／失敗と取得できた指標名のみです。ページ上に見える本文・日時・所有者・指標だけを読み、非表示APIや通信レスポンスからの補完はしません。返信表示があれば対象外にし、否定できない場合は種別判定不能の保留です。プロフィール発見は表示された最大10件だけで、網羅性は保証しません。所有者の一致は投稿日時リンクのID・アカウントで確認します。判定不能な新規投稿はUIで確認してください。

投稿ページ1件あたり遷移25秒＋表示待ち12秒、リトライ0回、1実行の発見確認・追跡はそれぞれ最大10件です。混雑時は取り漏らしがあり、後から埋めません。CAPTCHAやアクセス制限の回避は実装しません。表示がない指標はnullです。認証エラー・404・ロード失敗を削除確定とは扱いません。

ローカル保存は一時ファイルから原子的に置換します。`tracking/.runner.lock` で競合を防ぎ、異常終了時は実行が停止したことを確認してロックを除去します。成功した投稿ごとに保存するため部分失敗時にも履歴を保持します。非公開チェックアウトの更新・pushは通常の別の認証済みGit操作で行ってください。このツールはブラウザのGitHubトークンにアクセスしません。

## 約1時間ごとの実行（初期状態は無効）

非公開側に `.github/workflows/track-reactions.yml` を追加しています。cronは毎時17分ですが、`jobs.track.if` の固定停止条件 `false &&` を取り除き、さらに `TRACKING_ENABLED=true` のリポジトリ変数を設定するまで手動dispatchも定期処理も動きません。本作業では有効化・課金・デプロイを行いません。

運用前に変更を両リポジトリへ反映し、実際の実行環境で少数URLを検証してください。無認証取得ができない場合、別のXセッションを非公開リポジトリのActions Secret `X_SESSION_JSON` に設定します。これは利用者ブラウザ内のGitHubトークンと別の認証です。短命のrunner tempに保存し、終了時に削除します。GitHub認証はその非公開リポジトリに限定したActions `GITHUB_TOKEN` のContents writeを使用します。公開コードのcheckoutは認証を永続化しません。利用者PATをSecretsへコピーしないでください。既存の認証規則と両立しない環境では有効化せず、手動実行を使ってください。

定期処理は最大20分、同じ書込グループで直列実行します。実際の取得日時を保存するためスケジュール遅延を正時取得と偽りません。再実行のrunIdはActions run IDです。Git pushが別のUI保存等と競合した場合は安全のため失敗し、強制上書きしません。失敗したrunner上の未push履歴は永続化されないため、運用前に競合監視や耐久保存先の検討が必要です。公開artifactに退避しません。

停止は `TRACKING_ENABLED` をfalseにし、個別投稿はUIの停止操作で制御します。7日を過ぎた投稿は次回予定から外れます。Actionsの実行自体は変数を止めるまで起動します。

## 費用・制約・確認範囲

Playwright・Chromiumは無料のソフトウェアですが、約720回/月のrunner起動＋ブラウザ準備・取得の実行時間が必要です。private GitHub Actionsの無料枠、ストレージ、超過単価は契約で異なります。1回T分なら約720T runner分/月が目安です。定額や実費は測定していません。Xのセッション失効、表示仕様変更、ログイン制限があり、継続取得は保証できません。[Xの現行利用規約](https://x.com/en/tos)（2026-09-30確認）は、原則として事前の書面許可なしのcrawling／scrapingを禁止しています。自分の投稿を取得する場合も無条件に許可されるとは扱いません。ブラウザ収集を運用する前に適用法・Xの許可／契約を確認してください。許可を確認できない場合は手動記録または公式APIを選び、定期ブラウザ取得を有効化しないでください。

この実行環境ではChromium起動を確認しましたが、Xの投稿・プロフィールへのブラウザ遷移は `net::ERR_HTTP_RESPONSE_CODE_FAILURE` で失敗しました。ログインなしでの実数取得・自動発見は未成功です。ログイン済みセッションは提供されておらず未検証です。合成DOMからの数値・概数・所有者判定はテストしていますが、実Xでの取得成功の証明ではありません。会話用クラウドブラウザの常時利用は前提にしていません。

ブラウザ方式が対象の環境で安定しなければ、公式X APIへの取得adapter差替えを検討してください。所有者タイムライン・public metrics、非公開指標の取得権限・認証・保持期間・レート制限を現行契約で確認する必要があります。[公式料金](https://docs.x.com/x-api/getting-started/pricing)を2026-09-30に確認した時点では前払いクレジットの従量制で、Post Readは1リソース$0.005、アプリ所有者本人の `GET /2/users/{id}/tweets` 等のOwned Readは$0.001です。同一リソースのUTC日内再取得は原則重複課金されませんが、例外があるsoft guaranteeです。仮に対象10件を毎日30日取得する場合、投稿読取りのみなら日内重複排除時はOwned Read $0.30／通常Read $1.50、時間ごとに全て課金される場合は$7.20／$36が目安です。新規発見・ユーザー等の追加読取り、税、runner費用は別で、実費の保証ではありません。現行単価・利用上限・表示回数等の提供範囲はDeveloper Consoleで確認してください。公式API adapterや有料サービス契約は未実装・未実施です。手動登録・手動記録は追加サービス費用なしで利用できます。

## 検証・更新

```sh
npm ci
npm test
CHROMIUM_PATH=/usr/bin/chromium npm run test:ui
TWITTERDB_DATA_DIR=/absolute/path/TwitterDB-data node tools/audit.mjs
```

`npm test` は合成データだけで返信・リポスト・引用、7日判定、欠測とゼロ、減少、重複、部分失敗、時系列漏洩、初動モデル、最終期間を使わない選択、キャッシュ、保存競合を確認します。UIテストは認証必須・モックGitHub API・スマホ幅・本文エスケープ・手動記録・停止再開・再読込・合成DOM取得を確認します。実Xや秘密トークンは使いません。

監査ツールは**UIと同じ分割アーカイブ**を調べます。旧 `tweets.js` と分析データに差があっても、存在しない属性を埋めません。完全なXエクスポート形式（edit_info・entities・retweetedの存在）では返信キー省略は非返信として扱い、簡略形式での省略は判定不能です。本文の@だけでは確定しません。引用の構造化属性がない元データでは引用を復元しません。

結果は非公開側の `tracking/archive-audit.json` と `tracking/snapshot-evaluation.json` に出力します。投稿件数・期間・項目・欠損・重複・取得時点の不明・除外・推論時間と、検証／テスト期間、MAE、log1p MAE、実績幅の被覆率・幅を保存します。予測区間は未校正なので被覆率・幅はnullで明示します。実データ由来の結果を公開リポジトリへコピーしないでください。モデルを変更する時は `MODEL_VERSION` を更新し、合成テストと過去→未来の検証を再実行してください。
